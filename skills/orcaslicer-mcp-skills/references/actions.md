# Speed Dial commands

Generated by OrcaSlicer's `tools/mcp/gen_skill_reference.py` from its command reference
(`tests/data/command_catalog.json`); do not edit it by hand.

These are the commands a person picks in the Speed Dial, by section. Call one with
`call_tool {"tool": "<key>", "args": {...}}`, or run its tile with `run_action {"id": "<key>", "args": {...}}`;
`search_tools {"tool": "<key>"}` gives its whole schema, and its examples when it has some. Some are the
person's own. Action Replay, Run Script, Take Screenshot and the calibration dialogs have a tool for agents
(`run_replay`, `run_script`, `screenshot`, `generate_calibration_test`); the wiki and YouTube links, About,
the plugin hub and the configuration folder (`open_wiki`, `open_youtube`, `help_about`, `install_plugin`,
`help_open_config_folder`) are left to the person.

A command whose schema has `silent`, or whose description says what it does with no arguments, does what a
person's pick does when called with none: one that asks in a dialog opens it, which a call reports as
`blocked_by_dialog`. Given its arguments, or `silent: true` if it takes `silent`, it runs without asking and
needs the arguments marked required. A command whose schema requires an argument has no person's form
(`go_to_tab {}` is refused), and one whose dialog is what it does opens it with arguments too
(`export_config {"path": "/abs/dir"}` only spares it the folder question).

The Design section lists the Design tab's commands that have a tile; `search_tools {"group": "Design"}` lists
them all, and `references/cad.md` covers them. They run only with the CAD feature on, which a person turns on
in Preferences > Features before restarting OrcaSlicer: `get_app_state.design_tab` says whether the Design tab
is on, and `cad_note`, while its commands cannot run, how to turn it on (a test instance gets it with
`tools/mcp/orca_mcp.py launch --cad`). A Design tile is in the Speed Dial, and `run_action` runs it, only while
the Design tab is shown in the tile's mode (in a sketch or outside one); `call_tool` runs its command from any
tab. Called with no arguments, a tile's command does what its right-click menu row does, which may be to act
at once (a Delete row deletes what is selected) or to decline.

A row whose arguments are written as a call's own (`{"type": "linear"}`, or `{}`) is one tool of its command:
`call_tool` given exactly those arguments opens that tool, as a person's pick of its tile does, and any other call
runs the command from its arguments. The tile has an id of its own, which `search_actions` gives, and `run_action`
runs it with no arguments or with exactly those.

`go_to_layer` and `go_to_tab` need their value. A typed tool that is also a tile (`new_project`,
`save_project`, `start_recording` and `stop_recording`) is in the tool list too.

| `export_gcode` | Export G-code | `overwrite` (boolean): Replace a file that exists already. Default false.<br>`path` (string): Absolute path of the .gcode file to write. | Export the current plate's G-code. | `export_stl` | Export STL | `overwrite` (boolean): Replace a file that exists already. Default false.<br>`path` (string): Absolute path of the .stl file to write. | Export all objects as one STL. With a path, writes there without a dialog. |
| `export_3mf` | Export 3MF | `overwrite` (boolean): Replace a file that exists already. Default false.<br>`path` (string): Absolute path of the .3mf file to write. | Export the model as a .3mf without slicing data. With a path, writes there without a dialog. |
| `export_sliced_file` | Export Sliced File | `overwrite` (boolean): Replace a file that exists already. Default false.<br>`path` (string): Absolute path of the .gcode.3mf file to write. | Export the current plate's sliced file (.gcode.3mf). With a path, writes there without a dialog. |

One recording at a time: one a replay or script starts ends with it, a client's when the server is turned off. With encode, the stop_recording that reports it also encodes it to an MP4 beside it, as the Start Recording command does, and the .mkv is deleted once the MP4 is written unless keep_raw_video_file; encode_recording makes an MP4 of any recording later. Called with no arguments, it opens the Start Recording dialog instead, as the Start Recording command does (blocked_by_dialog): its controls are named after their settings for set_widget_value, answer_dialog "Start recording" starts the person's recording, which neither the end of a replay or script nor the server turning off ends, and the dialog remembers the settings; silent: true starts one here at once with the defaults. |
| `stop_recording` | Stop Recording | `silent` (boolean): true waits for the file and returns the report, and the encode job when the recording has one; a call with no arguments stops as the Stop Recording command does. | Stop the running recording. Call it with silent: true for the report: it waits for the file and returns it with its seconds, frames captured and written, frames dropped when encoding fell behind, failed when they could not be encoded, or skipped when the window could not be captured, the size, the mean UI-thread time a capture took (capture_ms), and why it ended. A recording that ended on its own (max_seconds, the replay or script that started it ended, a write error) is reported once by the next stop_recording. For a recording started with encode, it then starts the MP4 encode and returns it under encode: a job, whose wait {for: "job"} returns encode_recording's result, whose raw_video_file_deleted says whether the .mkv was deleted. Called with no arguments, it stops the recording as the Stop Recording command does, whoever started it: without waiting for its file, it shows the person a notification naming it and replies with its path; the next stop_recording with silent: true reports it as ended stopped_in_app. |
