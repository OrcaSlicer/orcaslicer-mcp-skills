# Speed Dial commands

Generated by OrcaSlicer's `tools/mcp/gen_skill_reference.py` from its command reference
(`tests/data/command_catalog.json`); do not edit it by hand.

These are the actions a person picks in the Speed Dial, by section. Each runs a command with the arguments
its row gives. Call the command by its name, with those arguments or others, and one the tool list does not
show with `tool_call {"tool": "<command>", "args": {...}}`; `tool_search {"tool": "<command>"}` gives its whole
schema, and its examples when it has some. `action_run {"id": "<key>"}` runs an action as a call with the
action's arguments does. Action Replay, Run Script, Take Screenshot and the calibration dialogs have a command
for agents (`replay_run`, `script_run`, `window_screenshot`, `calibration_generate_test`); the wiki and
YouTube links, About, the plugin hub and the configuration folder (`app_open_web_page`,
`window_open {"window": "about"}`, `app_show_config_folder`) are left to the person.

A call with exactly an action's arguments is the action's own call: where the action asks in a dialog, the call
opens it, which it reports as `blocked_by_dialog`, and where the action acts on the selection, so does the call.
An action whose menu item does what its command does (a camera view, Select All, Deselect All, Auto-Arrange,
Auto-Orient, Refresh Plugins) runs the command's own function and replies as the command does. Any other
arguments, or `silent: true` where the schema has `silent`, run the command without asking, with the arguments
its schema marks required. Go to tab and Go to layer collect their value in the Speed Dial: `action_run` gives
such an action its one value (`{"tab": "preview"}`, `{"percent": 50}`), and the command takes it as the argument
its row names. A command whose dialog is what it does opens it with arguments too
(`preset_export {"path": "/abs/dir"}` only spares it the folder question).

The Design section lists the Design tab's commands that have an action; `tool_search {"group": "Design"}` lists
them all, and `references/cad.md` covers them. They run only with the CAD feature on, which a person turns on
in Preferences > Features before restarting OrcaSlicer: `app_state.design_tab` says whether the Design tab
is on, and `cad_note`, while its commands cannot run, how to turn it on (a test instance gets it with
`tools/mcp/orca_mcp.py launch --cad`). A Design tab action is in the Speed Dial, and `action_run` runs it, only
while the Design tab is shown in the action's mode (in a sketch or outside one); `tool_call` runs its command
from any tab. Called with no arguments, an action's command does what its right-click menu item does, which may
be to act at once (a Delete item deletes what is selected) or to decline.

A Design row whose arguments are written as a call's own (`{"type": "linear"}`, or `{}`) is one tool of its
command: `tool_call` given exactly those arguments opens that tool, as a person's pick of its action does, and
any other call runs the command from its arguments. The action has an id of its own, which `action_search`
gives, and `action_run` runs it with no arguments or with exactly those.

The tool list does not show `settings_toggle_developer_mode`, `window_save_screenshot` and
`script_toggle_panel`, menu items that take no arguments: call them with `tool_call`.

## Commands

| key | title | runs | does |
|---|---|---|---|
| `undo` | Undo | `undo {}` | Take back the last change of a history, as Edit > Undo does. history design is the Design tab's: the last feature added, edited, deleted, moved, shown or hidden, or renamed, or variable changed, or in a sketch session the last drawn shape; project is the project's. Without history, the Design tab's while it is shown, else the project's. Reply: history and, for the Design tab's, result: scope (design or sketch), undo_depth, redo_depth, features, bodies and generation; entities in a sketch. |
| `redo` | Redo | `redo {}` | Put back what undo took back, until the next change, as Edit > Redo does, in the history undo takes. Reply as undo's. |
| `load_project` | Load Project | `project_open {}` | Open a project through the Open dialog (it asks first if the current project has unsaved changes); project_open with a path opens that file without a dialog. |
| `new_project` | New Project | `project_new {}` | Runs project_new with no arguments, as New Project does: a new, empty project, after asking about the unsaved changes if there are any. |
| `save_project` | Save Project | `project_save {}` | Runs project_save with no arguments, as Save Project does: to the project's file, or through a file dialog when it has none. |
| `save_project_as` | Save Project As | `project_save {"save_as": true}` | Save the project as a .3mf file through the save dialog. project_save with a path saves there without a dialog; a name ending in .gcode.3mf is refused (project_export {format: "sliced_3mf"} writes that). |
| `go_to_tab` | Go to tab... | `view_set {"tab": <tab>}` | Switch to a main window tab. |
| `go_to_layer` | Go to layer (percent) | `view_set {"layer_percent": <percent>}` | Show the Preview tab at a layer chosen as a percentage of the layer range; an error while the Preview has no layers (slice first). |
| `open_preferences` | Preferences | `window_open {"window": "preferences"}` | Open the Preferences dialog. window_open with a tab, and a key on it, opens it on that tab with that preference's control scrolled into view and focused (shown on its own tab). |
| `open_action_replay` | Action Replay | `window_open {"window": "action_replay"}` | Open the Action Replay window, where a person opens a replay file, reads its steps and replays them. Agents run replays with the replay_run tool instead. |
| `take_screenshot` | Take Screenshot | `window_save_screenshot {}` | Save a PNG of the main window in the folder Start Recording saves in (the person's Downloads unless they chose another) and show the person a notification naming it; the reply has its path. Agents use the window_screenshot tool, which returns the image. |
| `toggle_run_script_panel` | Run Script | `script_toggle_panel {}` | Show or hide the Run Script panel, where a person writes and runs Python scripts cell by cell. Agents run Python with the script_run tool instead. |
| `start_recording` | Start Recording | `recording_start {}` | Runs recording_start with no arguments, as Start Recording does: the Start Recording dialog, whose Start recording starts the person's recording, which neither the end of a replay or script nor the server turning off ends. |
| `stop_recording` | Stop Recording | `recording_stop {}` | Runs recording_stop with no arguments, as Stop Recording does: it stops the recording, whoever started it, and shows the person a notification naming its file. |
